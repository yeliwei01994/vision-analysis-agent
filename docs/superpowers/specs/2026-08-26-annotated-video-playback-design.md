# YOLO 完整检测回放设计

## 目标

视频任务处理完成后，自动生成一份与原视频时长一致的 YOLO 检测回放视频。回放保留所有原始帧，并在检测到目标的帧上绘制目标框、类别、置信度和时间戳；原视频文件保持不变。事件详情页提供原始视频与检测回放的切换播放，并在回放尚未生成或生成失败时展示明确状态。

## 范围

第一版只支持本地测试环境和现有视频任务 worker，不引入 Docker、实时流式编码或 LLM。检测回放在一次任务处理期间生成，和现有 YOLO 推理共享逐帧检测结果。事件生成、事件流和证据图片不能依赖回放生成成功。

## 方案

worker 在读取每个抽帧并调用 YOLO 后，同时将归一化检测框转换为原始图像像素坐标，绘制到帧副本上。所有标注帧按原始顺序写入临时目录，再使用本机已有的视频编码能力合成为 MP4，并通过现有媒体目录提供访问。编码完成后将回放 URL 写入视频任务的可选字段；失败时清理临时文件、记录错误并保留原视频和已有事件结果。

标注规范：

- 框使用检测类别对应的稳定颜色；
- 标签显示类别和百分比置信度，例如 `person 86%`；
- 右上角显示当前时间戳；
- 可选绘制当前规则区域，使用独立的虚线样式；
- 坐标始终使用 YOLO 归一化结果转换后的原图像素坐标，避免画框偏移。

## 数据与接口

视频任务增加可选字段 `annotated_video_url` 和 `annotated_video_status`，状态为 `pending`、`ready` 或 `failed`。数据库迁移保持向后兼容，旧任务字段为空时前端仍可使用原有视频和证据帧。

新增或扩展媒体访问路径，使前端可以通过受保护的相对媒体 URL 播放回放。接口不返回本地绝对路径，也不允许通过路径参数访问媒体目录之外的文件。

worker 处理顺序：

1. 读取原视频并抽帧；
2. 调用 YOLO，保存检测结果和证据帧；
3. 生成事件；
4. 生成完整检测回放；
5. 持久化任务完成状态和回放状态。

如果第 4 步失败，任务仍可以完成，但回放状态为 `failed`，事件流继续可用。

## 前端详情页

详情区域增加：

- “原始视频”和“YOLO 检测回放”切换按钮；
- 回放生成中的加载状态；
- 回放失败原因和“重新生成”入口（第一版可先显示状态，不阻塞事件审核）；
- 完整视频播放进度条，并与现有检测时间轴同步；
- 点击时间轴检测点时，视频跳转到对应时间。

没有回放 URL 时不显示空白播放器，而是展示“检测回放尚未生成/生成失败”，同时保留证据图片和事件详情。

## 错误处理与兼容性

- 编码器不可用、帧损坏或磁盘空间不足时，记录可读错误并将回放标记为 `failed`；
- 原视频删除、事件删除和任务删除时同步删除对应回放文件；
- 旧数据库通过迁移补充可空字段；
- 前端兼容没有新增字段的旧 API 响应；
- 不能因为回放生成失败而把任务标记为整体失败。

## 验收标准

1. 上传并处理一个新视频后，任务详情能看到回放状态从生成中变为可播放；
2. 回放时长、帧顺序和原视频一致；
3. 至少验证 `person`、`boat` 两类检测框的位置、标签和置信度；
4. 无检测帧仍然存在，不会被丢弃；
5. 原视频播放不受影响；
6. 编码失败时事件流仍能返回，详情页显示失败原因；
7. 后端单元/集成测试覆盖状态持久化和媒体路径安全，前端测试覆盖播放器切换、加载和失败状态；
8. 前端测试、构建和 Rust 完整测试全部通过。
