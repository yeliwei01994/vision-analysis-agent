# 实时任务进展与用户友好型交互升级设计

## 1. 背景与目标

当前前端已经具备视频任务状态和 `progress` 字段，但用户体验存在三个主要问题：

1. 上传后主要依赖单任务轮询，视频任务页需要手动刷新。
2. 进度只表达百分比，不能说明任务当前正在做什么。
3. 任务完成或失败后，缺少清晰的结果入口和恢复操作。

本次升级的目标是让用户始终知道：

- 任务是否仍在运行；
- 当前正在处理哪个阶段；
- 进度是否在持续推进；
- 预计还需要等待多久；
- 完成后可以查看什么；
- 失败后应该如何恢复。

本设计只聚焦视频任务进展、任务中心和相关事件结果反馈，不改变现有事件审核、规则配置和视频回放的业务规则。

## 2. 设计原则

### 2.1 状态要表达下一步

任务状态不只使用颜色或英文枚举，而是使用用户能理解的阶段文案和下一步操作。整体状态参考 Linear 的有序工作流思想：状态应体现任务生命周期和推进关系，而不是仅作为标签展示。

参考：[Linear Issue Status](https://linear.app/docs/configuring-workflows)

### 2.2 进度要说明等待是否正常

可计算时使用确定性线性进度；无法计算时使用不确定进度，并明确当前阶段。进度条固定在所属任务卡片内，不能只在页面顶部展示全局 loading。

参考：[Material Progress Indicators](https://m2.material.io/components/progress-indicators)、[Apple Progress Indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)

### 2.3 结果和恢复动作就近出现

任务完成时直接提供“查看事件”和“播放检测回放”；任务失败时直接提供“查看原因”和“重新处理”。借鉴 GitHub Actions 对运行状态、步骤、错误和重新运行操作的集中呈现方式。

参考：[GitHub Actions Workflow Run Logs](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-workflow-run-logs)

### 2.4 黄金比例只用于宏观布局

黄金比例用于建立视觉主次，不机械套用到所有组件尺寸。事件列表与事件详情建议使用约 `38.2% : 61.8%` 的宽度关系，保证详情侧的视频、检测框、证据帧和分析内容拥有主视觉空间。组件内部继续使用 8px 间距基准和 16/24/32px 的层级间距。

## 3. 目标用户流程

```text
选择视频
  ↓
上传完成，立即创建任务卡片
  ↓
排队 / 视频解析 / 目标检测 / 事件分析 / 生成回放
  ↓
任务完成，自动刷新事件结果
  ↓
查看事件或播放检测回放
```

异常流程：

```text
任务失败
  ↓
展示原因、失败阶段和最近更新时间
  ↓
用户选择重新处理或查看错误详情
```

用户可以在任务处理过程中切换到事件检索、规则配置或模型版本页面；任务状态不会因为页面切换而丢失。

## 4. 页面与布局设计

### 4.1 事件检索页：常驻任务状态条

在页面标题和数据概览之间增加任务状态条。单任务示例：

```text
┌─────────────────────────────────────────────────────────────┐
│ ● 正在处理  监控视频-01.mp4                                  │
│   目标检测中 · 已完成 35% · 最近更新：刚刚       查看任务详情 → │
└─────────────────────────────────────────────────────────────┘
```

多个任务时显示汇总：

```text
3 个任务处理中 · 8 个已完成 · 1 个失败             打开任务中心 →
```

要求：

- 固定在一致位置，避免用户到处寻找进度；
- 处理中任务显示当前阶段、进度和最近更新时间；
- 完成后短暂保留结果提示，再收缩成任务汇总；
- 失败任务显示失败数量，并提供进入任务中心的入口；
- 不阻塞事件检索页其他操作。

### 4.2 视频任务页：任务中心卡片

将现有以表格行为主的任务列表升级为卡片化任务中心。处理中任务展示：

```text
┌──────────────────────────────────────────────┐
│ 监控视频-01.mp4                    处理中     │
│ 正在生成检测回放                              │
│                                              │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━ 75%              │
│ 已处理 08:32 / 12:00                          │
│ 最近更新：3 秒前 · 预计剩余：约 20 秒           │
│                                              │
│ [查看实时详情]                         [取消] │
└──────────────────────────────────────────────┘
```

排序规则：

1. 处理中任务按最近更新时间倒序；
2. 失败任务置于已完成任务之前；
3. 已完成任务默认使用紧凑行展示；
4. 支持按状态筛选；
5. 保留编辑文件名和删除能力，处理中任务禁止删除，取消能力由后端支持后启用。

### 4.3 任务详情抽屉

点击“查看实时详情”打开右侧抽屉，展示任务阶段时间线、最近进展和可用操作：

```text
┌─────────────────────────────────────┐
│ 任务详情                       ×     │
├─────────────────────────────────────┤
│ 监控视频-01.mp4                     │
│ 正在生成检测回放                     │
│                                     │
│ ● 视频读取              已完成       │
│ │                                   │
│ ● 目标检测              已完成       │
│ │                                   │
│ ◉ 事件分析              进行中       │
│ │                                   │
│ ○ 检测回放              等待中       │
│                                     │
│ 最近进展                             │
│ 14:32:08 已发现 12 个候选事件         │
│ 14:32:12 已完成 75% 视频分析          │
│                                     │
│ [查看日志] [取消任务]                 │
└─────────────────────────────────────┘
```

第一期只实现阶段时间线和最近进展，不要求完整日志检索系统。

## 5. 任务状态与阶段模型

### 5.1 对外任务状态

| 后端状态 | 用户文案 | 视觉状态 | 可用操作 |
|---|---|---|---|
| `pending` | 等待处理 | 中性 | 查看详情、删除 |
| `processing` | 正在处理 | 青绿色 | 查看详情、取消（后端支持后） |
| `completed` | 处理完成 | 成功绿 | 查看事件、播放回放 |
| `failed` | 处理失败 | 红色 | 查看原因、重新处理 |
| `cancelled` | 已取消 | 灰色 | 重新处理、删除 |

### 5.2 processing 阶段

`processing` 内部使用阶段字段表达当前工作：

1. `preparing`：正在准备视频；
2. `reading`：正在读取视频；
3. `extracting_frames`：正在抽取关键帧；
4. `detecting`：正在进行目标检测；
5. `analyzing_events`：正在分析事件；
6. `generating_playback`：正在生成检测回放；
7. `finalizing`：正在整理分析结果。

后端仍可保留现有 `status` 和 `progress` 字段。新增阶段字段和用户提示字段，不破坏已有 API 消费方。

## 6. 实时数据流设计

### 6.1 推荐机制

采用 SSE 为主、轮询为兜底：

```text
上传视频
  ↓
创建任务
  ↓
前端立即显示任务卡片
  ↓
SSE 推送任务进展
  ↓
更新任务状态条、任务卡片、详情抽屉
  ↓
完成后刷新任务、事件和回放信息
```

### 6.2 任务进展事件

建议新增统一事件结构：

```ts
interface JobProgressEvent {
  job_id: string;
  status: 'pending' | 'processing' | 'completed' | 'failed' | 'cancelled';
  stage?: string;
  progress: number;
  message?: string;
  updated_at: string;
  estimated_remaining_ms?: number | null;
  sequence: number;
}
```

其中：

- `sequence` 用于防止旧事件覆盖新状态；
- `updated_at` 用于显示“刚刚更新”和检测任务是否长时间无变化；
- `estimated_remaining_ms` 没有可靠数据时返回 `null`，前端不伪造剩余时间；
- `message` 用于显示用户可理解的阶段提示。

### 6.3 断线和恢复

- SSE 断开时显示“实时连接中断，正在重新连接”；
- 自动降级为 2～5 秒轮询；
- SSE 恢复后通过完整任务查询校准状态；
- 页面刷新后通过 `/api/v1/jobs` 恢复所有任务；
- 前端任务状态池以 `job_id` 为 key；
- 任务进度不允许倒退，终态不允许被处理中事件覆盖。

## 7. 完成、失败和异常反馈

### 7.1 完成

```text
✓ 处理完成
已生成 12 个事件，检测回放已就绪

[查看事件] [播放检测回放]
```

完成后：

- 自动刷新事件列表；
- 可选自动选中当前任务生成的第一条事件；
- 显示事件数量和回放状态；
- 顶部任务条保留 5～10 秒后收缩。

### 7.2 失败

```text
! 视频处理失败
视频读取超时，请确认文件可访问后重试

[重新处理] [查看错误详情]
```

错误信息必须包含：发生了什么、可能原因、用户下一步可以做什么。后端暂时无法提供稳定错误码时，前端使用有限的错误类型映射，不直接展示 Worker 堆栈。

## 8. 视觉与动效规范

- 保留现有深色视觉风格和青绿色主色；
- 处理中使用青绿色线性进度条和轻微流动动画；
- 排队中使用静态等待状态，不伪造百分比；
- 成功使用勾选图标和短暂高亮；
- 失败使用红色状态、文字说明和恢复按钮；
- 所有动效使用 150～300ms 的微交互时长；
- 开启 `prefers-reduced-motion` 时关闭装饰性动画；
- 图标使用统一 SVG 图标，不使用 emoji 作为结构化图标；
- 所有主要操作点击区域不小于 44px；
- 状态表达不能只依赖颜色，必须同时有文字或图标。

## 9. 实施范围

### Phase 1：实时任务中心

目标：解决“用户不知道任务是否还在运行”。

- 统一前端任务状态池；
- 自动刷新所有任务；
- 增加事件检索页顶部常驻任务条；
- 增加任务中心卡片；
- 增加阶段文案、进度条、最近更新时间；
- 上传后立即显示任务卡片并自动聚焦；
- 完成后刷新事件列表。

### Phase 2：任务详情与结果闭环

目标：让用户知道任务具体进行到了哪一步。

- 增加右侧任务详情抽屉；
- 增加阶段时间线；
- 增加最近进展列表；
- 增加完成后的查看事件、播放回放操作；
- 增加失败原因和重新处理入口；
- 建立任务与事件结果的关联展示。

### Phase 3：SSE 与同步可靠性

目标：从前端轮询升级为后端事件驱动的实时进度。

- 新增 SSE 任务进度接口；
- Worker 在关键阶段发布进度事件；
- 增加 SSE 断线重连和轮询兜底；
- 增加 `sequence` 版本校验；
- 增加多任务并发同步测试；
- 根据历史阶段耗时计算预计剩余时间。

## 11. 验收标准

### 交互

- 上传后 300ms 内显示任务卡片或明确的上传状态；
- 不手动刷新即可看到任务变化；
- 用户可以看到当前处理阶段，而不只是百分比；
- 页面切换后任务继续更新；
- 刷新浏览器后可以恢复正在处理的任务；
- 完成后可以直接进入事件结果或检测回放；
- 失败后可以看到原因并发起重新处理；
- SSE 断开时显示连接状态并自动降级；
- 进度不会倒退，终态不会被旧事件覆盖。

### 视觉

- 事件列表与详情区域约为 `38.2% : 61.8%`；
- 使用 8px 间距基准；
- 主要任务卡片具备明确的标题、阶段、进度、更新时间和操作区域；
- 375px 宽度下不出现横向溢出；
- 开启减少动效后仍能理解任务状态；
- 关键状态不依赖颜色单独表达。

### 回归

- 事件搜索、筛选、分页和导出保持可用；
- 事件确认、忽略、审核备注和删除保持可用；
- 原始视频和 YOLO 检测回放切换保持可用；
- 规则配置和模型版本页面不受影响。

## 12. 非目标

本阶段不包含：

- 完整的 Worker 日志检索平台；
- 浏览器系统通知和邮件通知；
- 跨用户任务权限模型；
- 任务优先级和资源调度策略；
- 复杂的取消后端语义，除非现有 Worker 已具备安全取消能力。
